# Aegis Node Storage Audit (Pre-R2)

This document maps out the current local storage behaviors within the Aegis Node architecture, establishing the baseline before Cloudflare R2 object storage is introduced.

## SQLite Database
* **Current Location:** `./aegis_node.db` (root of the project, configured via `DATABASE_URL` in `config.py`)
* **Purpose:** Persistent relational tracking of datasets, files, scan results, threat intelligence records, and verification states.
* **Retention:** Permanent.
* **Access Pattern:** Read/Write by the FastAPI application.

## File Storage Locations

All file storage is currently managed by `backend/services/file_service.py`, which resolves to `data/` at the project root or falls back to `/tmp/data/` if permission is denied.

### 1. Uploaded Originals
* **Location:** `data/samples/` (and dynamically during upload `data/samples/*.tmp`)
* **Purpose:** Stores original user-uploaded files, maintaining them while scans run. Streaming chunks are written here to enforce memory limits.
* **Retention:** Temporary (conceptually) if Render ephemeral disks are used, but the codebase treats them as persistent artifacts. When files are determined to be malicious, they may be moved to quarantine.
* **Cleanup:** Kept indefinitely by default on local disks, wiped periodically on Render.

### 2. Quarantined Files
* **Location:** `data/quarantine/`
* **Purpose:** Isolation for identified malicious samples.
* **Retention:** Same as originals.
* **Cleanup:** No automated garbage collection.

### 3. Sanitized Artifacts
* **Location:** `data/sanitized/`
* **Purpose:** Stores the scrubbed/neutralized versions of malicious or suspicious files generated by the remediation engine.
* **Retention:** Persistent (to serve to end users).
* **Cleanup:** No automated garbage collection.

### 4. Security Reports
* **Location:** Not stored as physical files!
* **Purpose:** JSON security reports are returned dynamically via API endpoints and their metadata is stored in SQLite. There is no `data/reports/` directory currently.

### 5. Benchmark Data (Research)
* **Location:** `research/benchmark/dataset/`, `research/benchmark/ground_truth/`, `research/benchmark/results/`
* **Purpose:** Contains the A–F scientific ablation benchmark artifacts.
* **Retention:** Strictly persistent and source-controlled via Git. Must not be altered by the R2 migration.

## Next Steps
The R2 adapter will intercept the file storage behaviors currently mapped to `data/samples/` and `data/sanitized/`, treating them as objects in Cloudflare R2 instead of local files. SQLite will remain local/ephemeral for now per the Phase 8B requirement.
